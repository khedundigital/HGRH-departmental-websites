# HGRH Digital Patient Access — unofficial demonstration

A public-facing **prototype**, not an approved hospital website. It demonstrates a caregiver journey through Paediatrics while operational and clinical content awaits hospital verification. No patient data is collected, no booking or submission system exists, and there is no O&G content. The original source repository and its deployment remain unchanged.

## Public website and editing

`site/` is the complete deployable website. Open `site/index.html` locally, upload the directory contents to any conventional static host, or ZIP the directory. No npm, Node, framework, server or build step is required. Edit the HTML files directly; shared colours, typography and components are in `site/assets/css/tokens.css` and `main.css`; print rules are in `print.css`. Keep links project-relative so they work under the GitHub Pages subpath and in a ZIP. Navigation is repeated in each HTML file so it remains available without JavaScript. Ten English routes cover the home page and nine Paediatrics pages: home, admissions, clinics, preparation, programmes, education, forms, FAQs and contact. Each has a matching static route under `/zu/`. The isiZulu route is an AI-assisted **draft demonstration**, labelled on every page, pending qualified translation and departmental clinical review. The education page links to direct WHO-hosted PDFs; the forms page links to official SASSA supporting PDFs. Two original printable question/checklist PDFs are in `site/documents/`.

The earlier clinic timetable and admission sequence appear as **historical prototype examples**, with warnings that they are unverified and unsuitable for planning a visit. The current official KZN Health hospital page is linked for confirmation; the earlier unverified emergency number and placeholder doctor names are omitted. Keep this boundary when editing. Do not add clinical advice or present draft translation as approved. Follow `docs/governance/approval-workflow.md` and update `docs/governance/content-register.csv` when content is reviewed. Language status is recorded in `site/data/translations/status.json`. If editing navigation across routes, update each HTML page or run the optional `python3 scripts/sync_navigation.py` helper; it is not used for publishing. The actual Care Dependency and Disability Grant **application** forms are obtained at SASSA offices under current government guidance; linked PDFs are supporting forms.

## Test

Run `python3 tests/check_site.py`. It checks routes, local links and fragments, landmarks, the warning, no forms or external CDN dependency, and publish isolation basics. After deployment run `python3 tests/check_live.py` to fetch every route and printable PDF and confirm working documents stay unpublished. Also inspect in a browser at mobile, tablet and desktop widths, keyboard focus, print preview and JavaScript disabled. The site should render and navigate directly from files.

## Deployment and rollback

GitHub Actions in `.github/workflows/static.yml` uploads **only** `site/` to GitHub Pages from `main`. GitHub repository Pages settings must be set to **GitHub Actions**. Target: `https://khedundigital.github.io/HGRH-departmental-websites/`. Watch the workflow run and fetch the live home, Paediatrics, Admissions and FAQs pages after pushing. To roll back, use GitHub's revert action or `git revert <implementation-commit>` on `main`, then push and verify a new Pages run. Do not force push. The original prototype files are under `prototype-archive/`, with the original homepage in Git history; the full two-commit source ancestry remains. The archive is outside the Pages artifact.
