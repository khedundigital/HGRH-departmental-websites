# O&G questionnaire-to-pages mapping (future task)

The owner is still completing the questionnaire. This is a structure for reviewing future answers, not a claim about services.

| Questionnaire evidence | Proposed route | Mandatory verification |
| --- | --- | --- |
| Department purpose, audiences, key tasks and authorised name | `/obgyn/` | Clinical lead and communications |
| Referral or booking process, arrival point, hours and contacts | `/obgyn/access.html` | Operations, patient administration and current source |
| Named services, eligibility and location | `/obgyn/services.html` | Department lead and each service owner |
| Visit preparation and patient instructions | `/obgyn/preparation.html` | Clinician plus operational reviewer |
| Repeated questions and answers | `/obgyn/faqs.html` | Owner of each answer |
| Emergency or urgent-care wording | Each relevant route | Clinical lead and hospital emergency governance |
| isiZulu and other language needs | All routes | Qualified translator and clinical reviewer |

For each field, capture the exact questionnaire response, source document or responsible person, date, review decision, public wording and expiry/review date. Unanswered or ambiguous fields are blockers for that claim, not invitations to write generic maternity advice. Keep the source questionnaire and review signatures outside this public repository if they contain personal or internal information. Publish only the minimum approved content. Reuse shared CSS and static HTML without creating a separate repository or runtime stack. Record cross-department newborn content ownership before linking from O&G to Paediatrics.
